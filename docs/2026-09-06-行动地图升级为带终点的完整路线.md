# 行动地图升级：从「验证卡片」到「带终点的完整路线」（2026-09-06 定论）

## 一、背景与拍板过程

- 用户提交飞书文档《转行自救指南（六周计划）》参考。此前多轮澄清后确定：行动地图不能停留在"几张孤立的验证卡片"。
- 用户拍板补上的五样"踏实感"：① 终点与毕业感 ② 全程总览一张表 ③ 周节奏 + 当天可见结果（后续收缩为**带周次、不带到天**）④ 手把手的输入浓度 ⑤ 终点锚在求职/投递状态。
- 用户关键追问："怎么确定生成的内容符合当前的求职要求？而不是误导" → 引出四条**真实性纪律**。
- 最终形态：**决策验证引擎 + 执行路线**（带终点、全景、周次、证据、现实回填、毕业检查表），仍不脱离"先验证判断"的定位。

## 二、四条真实性纪律（治"误导"，产品机制而非话术）

1. **只写"这次真搜到的东西"，不凭模型记忆发明**
   任何"这行要什么 / 这条路通不通 / 该学什么 / 行情如何"的事实句，必须能指回本次实时检索到的真实语料；做不到就降级成"这块依据不足 → 你的任务就是去拿一手事实"，宁可薄，不许编。（延续此前防"问陶瓷答 AIGC"的串味规则，升级到事实层。）
2. **证据可点开核对**
   路线里引用了语料的动作，带"依据"入口（来源标题+原文链接）；引用不了就明标"待验证"。
3. **内容标时间**
   页面顶部标注"依据 {检索日期} 检索的 N 条真实资料整理；投递前再核一眼最新 JD"（仿指南的"资源维护日期"）。
4. **真实世界当裁判，AI 不当裁判**
   走完路线的验收全部对准现实反馈（真 JD 有没有这条、真从业者是否这么说、投递有没有回复），配合"现实回填"形成闭环。

## 三、数据结构：roadmap（v2）

在保留现有平铺 `data.actions[]`（8 字段，兼容旧存档/导出）基础上，升级版完整路线为：

```jsonc
{
  "roadmap": {
    "version": 2,
    "generatedAt": "ISO时间戳",
    "horizon": "6周",                    // 由时间压力分桶推：urgent≈2~3周 / short≈约6周（原4~6周，见文末落地说明）/ long≈8~12周
    "goal": {                            // 终点卡
      "text": "第6周你交得出：1份改到能投的简历 + 已投20份 + 能就你的判断讲3分钟",
      "basis": "根据你填的时间压力（一个月内）与目标而定"   // 不吃"待遇/成功率承诺"
    },
    "phases": [                          // 全程总览（逐阶段连续周次）
      {
        "no": 1,
        "week": "第1~2周",
        "title": "先验证方向是否值得投",
        "focus": "这阶段要判断/办成的一件事",
        "phaseDone": "做到什么算这阶段过",
        "tasks": [                       // 每条沿用八字段
          {
            "when": "第1周", "day": "",
            "hypothesis": "要验证的关键判断（一句话、可被事实推翻）",
            "where": "去哪儿做：平台/渠道+搜什么关键词",
            "steps": "怎么操作：一步步、带数字",
            "done": "做完算成：交付什么",
            "goSignal": "出现哪些说明该坚持/加码",
            "stopSignal": "出现哪些说明该收手/换路",
            "role": "r1|r2|r3|all",
            "ev": "来源编号或 verify"    // 见四
          }
        ]
      }
    ],
    "graduation": {                      // 毕业检查表 + 终点只看三件事
      "checklist": [{ "text": "…", "verify": "拿什么现实反馈验" }],
      "judge3": ["1. …", "2. …", "3. …"]
    }
  }
}
```

- **阶段内生成为"节奏序列"而非散点**：任务按 先查证 → 做小验证 → 交付 → 找反例/反对意见 的顺序排列（指南的节奏思想，不叫课表）。
- `task.ev`：`"来源3"`（引用本次语料第 N 条）或 `"verify"`（该任务本身就是去拿一手证据，不依赖语料）。后端 `linkEvRefs` 把编号解析成 {title,url} 供前端展开原文；老/兜底路线统一给 `verify`。

## 四、生成策略

| 环节 | 内容 | 说明 |
|---|---|---|
| 主炼金 `/api/alchemy` | 生成对峙墙 + 辨向自测 + **初版平铺 actions**（8字段，维持现状） | 一次直答，不做 roadmap，避免单次输出过长被截断 |
| 升级路线 `/api/actions` | 输入 topic / roles / quizResult / persona / **data.sources（本次语料）** → 输出 `{ roadmap }` | 事实锚 = 语料原文注入 prompt；要求事实句只能挂语料编号或标 verify |
| 触发时机 | 用户答完自测、**首次点进第④步**才请求（手动"重做完整路线"同接口） | 替代"答完即后台预取"，省额度防浪费；保留初版兜底 |
| 兜底 | 无 secret / 直答失败 → `buildFallbackRoadmap(fallbackActions)` 包一层 roadmap | 新 UI 在任何情况下都有东西可渲染 |

## 五、现实回填闭环（拍板：要做）

- 每条任务除"勾掉已完成"外，可回填验证结果：`属实`（站得住）/ `打脸`（被推翻）/ `不确定`。
- 本地持久化：`alchemy:verdicts:<topic>` 存 `{ "<phaseNo>-<taskIndex>": "up|down|unclear" }`。
- 推进规则（前端本地判定，不消耗 AI）：
  - 阶段内全部任务"已做"且无 `down` → 该阶段标记完成，解锁下一阶段，顶部亮"进入第 X~Y 周"；
  - 出现 `down` → 该阶段亮"🚩 出现收手信号：第 {no} 阶段 {hypothesis} 被现实打脸，先回看它的 stopSignal，复盘是换路还是换做法"；
  - `unclear` 累积 → 提示"证据还不够，先别下结论"。
- 勾选/回填随存档可回看；导出 Markdown 带勾选与回填状态。

## 六、兼容与回退

- 旧存档只有 `data.actions[]`（无 roadmap）→ ActionMap 回退渲染现有平铺卡片（原 UI），顶部提示可"生成完整路线"（需重进流程或手动触发）。
- `exportMd` / `recordToText`：actions 字段已是 8 字段（新代码曾用 task/why，需修正），并支持 roadmap 章节。
- MOCK/演示模式：`fallbackActions` 路线包装成 roadmap 后，新 UI 可全量演示。

## 七、代价与额度

- 初版 1 次直答（现状）+ 完整路线 1 次（吸收 quiz 与语料，仅进④才触发，单次 token 放宽到 ~2500）。
- 直答 100/天：每用户完整流程约 2 次主直答（原先已 ~2 次），实际触发仅在进④后，整体用量可控；保留 `AUTO_REGEN_CAP` 额度护栏语义（对"完整路线"生效）。

## 八、落地实现与实测（2026-09-06 下午，桌面运行版已上线）

**问题**：原 generateActions 指令只写"3 段决策验证（每段≥3 条、共 9~12 条）"，产出偏"验证假设小卡片"，离《转行自救指南》"分周、每周有输入→产出→验收"的浓度有差距。

**改动（均在桌面副本 zhihu.js，已同步开发仓库）**
1. **生成指令重写**：先要求模型从用户本次困惑/目标里认"目标岗位"，整条路线围绕该岗位真实要求展开（岗位要什么→还差什么→做什么作品证明→怎么投），严禁套建档行业/"AI产品经理/AIGC"默认设定；内置"通用六周骨架"只作节奏模板（岗位认知→一手调研→技能/做法评估→做作品→打磨公开→求职冲刺），具体每周学什么由模型按目标岗位改写。
2. **阶段数对齐 horizon**：约6周→正好6个阶段、week 依次"第1周"…"第6周"；约2~3周→3段；约8~12周→6段写周区间。short 桶 horizon 由"约4~6周"改为"约 6 周"（`routeHorizon`）；兜底包装 short 的周标签改为"第1~3周 / 第4~6周"。
3. **压缩单次输出**：每阶段 1~2 条任务、全路线 6~12 条（宁精勿滥）；每周排 2 条=输入练习+交付&反例，排 1 条=完整周任务（steps 走"学→拆→练→交付→反例"）；每条 steps 2~5 步一句话。要求每周至少一条任务 done 是"求职拿得出手的实物"并带数量+验收点（岗位地图≥N条JD/访谈纪要/可公开作品链接/简历PDF+投递漏斗），杜绝"了解一下"式伪交付。
4. **直答超时放宽**：`zhihuZhida` 增加可选 `timeoutMs`（默认 40s 不变）；路线生成传 60s、BUDGET 65s；**重试规则改为首轮快速失败（<8s）才重试**，首轮跑满超时的不重试，避免双倍额度与等待。
5. 四层约束保留：role 分配按最信派+盲区、ev 只许【来源N】或 verify、graduation 4~6 项"当场能打开材料证明"、judge3 三句。

**实测（真实直答，2026-09-06）**：topic「大三学生想转做『AI 视频生成』方向的产品实习，一个月内怎么做出能投递的作品集」→ 30.6s 一次成功（fallback:false）：horizon=约6周；6 个阶段 week=第1周…第6周；每阶段 1~2 条任务、每周均有实物交付（岗位地图≥10条去重JD+词频+差距表 / 拆解3个爆款案例 / 工具评测 / 第一版作品 / 发布+反馈 / 简历+≥15份真实投递）；平台与工具贴合目标岗位（BOSS直聘/实习僧搜"AIGC产品实习"，可灵/即梦，城市杭州）；8 字段齐全，go/stop 具体可判。

**遗留观察**：直答偶发慢（>60s）时仍会降级兜底；6~12 条上限是为了压在 40s 量级输出，后续如需每周更细的日任务粒度，需重新评估单次直答能力或改流式/分阶段生成。
