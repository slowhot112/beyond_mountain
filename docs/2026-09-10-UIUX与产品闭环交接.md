# 山外山本轮改动交接

更新日期：2026-09-10

交付分支：`main`

远端仓库：`slowhot112/beyond_mountain`

## 一句话说明

这轮不是简单换皮。我把产品从“几个功能并排摆放”收敛成一条用户能理解的求职判断链路：先说清自己的困惑，再看有原文可追溯的不同观点，做一次辨向自测，最后用一个低成本现实任务验证判断，并让验证结果影响下一次使用。

知乎提供社区观点与真实来源，“看山”提供路径、反馈和陪伴。产品不替用户下结论，也不会未经确认替用户投递、联系或执行其他对外动作。

## 1. 产品主流程

当前主流程统一为：

`我的山径 → 标记位置 → 确认路标 → 观山台 → 观点与原文 → 辨向自测 → 行动路线`

本轮完成的关键收敛：

- 结果页不再把多个能力做成同权入口，第一主操作统一为查看观点与原文。
- 自测和完整路线成为后续步骤，第一次使用不会直接把一张很长的行动地图压给用户。
- 观点墙读完后，先提供一个短时间可完成的现实验证任务，再由用户决定是否继续自测和生成完整路线。
- 至少完成 4 道辨向题，才允许生成完整路线；信息不足时只展示初版，不把低置信度建议包装成确定结论。
- 页面切换会清理旧错误、回到顶部，并记录本轮真正访问过的节点。
- 完整路线只由本轮自测解锁，历史偏好不会直接替新问题解锁路线。

## 2. 建档与渐进补充

建档首屏已减到 3 个核心问题：

1. 你现在处于什么阶段。
2. 你想往哪里走。
3. 你现在最想判断什么。

行业、细分方向、城市和时间压力等信息被收入“补充路标”，默认不展开。这样用户可以先开始，只有当补充信息确实能提高匹配质量时再填写。

简历不是必填项，也不要求登录。用户可以只写一段经历摘要，或者完全跳过简历继续使用。

## 3. 刘看山的介入方式

刘看山现在是右下角常驻的陪伴助手，而不是一个一直打断用户的弹窗。

- 用户填完“你现在最想判断什么”并离开输入框后，延迟约 900ms 提示补充城市或方向。
- 提示只有“补充路标”和“暂时不用”两个明确动作。
- 选择“补充路标”后，页面会展开补充区域、滚动定位、聚焦并短暂高亮。
- 提示气泡与虚拟形象按钮已经拆开，修复了点击气泡却误开聊天面板的问题。
- 主动提示只出现在关键节点：首次进入、结果生成、行动路线生成，以及核心问题刚填写完成时。
- 打开聊天面板时，主动提示会收起；提示也会定时消失。

刘看山可以基于当前结果和相关历史做解释与准备工作，但关键决定仍由用户确认。它不会直接代表用户投递岗位、联系他人、公开发布内容或提交资料。

## 4. 观点墙与当前验证任务

观点墙已从“大段信息堆叠”调整成渐进阅读：

- 默认展开第一条值得先看的观点，其余观点只展示摘要、适用处境和来源数量。
- 每条观点统一展示主张、最强论据、适用处境、成立边界、对其他观点的质疑、匹配理由和原文来源。
- 长内容、检索范围、判断框架和任务细节按需展开。
- 不同观点使用稳定的山头颜色，并延续到自测和行动路线，帮助用户理解前后关系。

观点墙底部新增一个当前验证任务，固定回答四件事：

1. 要验证什么。
2. 需要什么输入。
3. 现在做什么。
4. 做到什么算完成。

“开始这一步”目前只记录当前页面状态，并明确告诉用户系统不会替他提交或联系任何人。

## 5. 自测与行动路线

辨向自测不再是通用性格问卷：

- 每道题都绑定当前观点墙中的具体角色和前提。
- 选项内容来自各观点的真实立场，不再使用“支持 A 派”一类空标签。
- 回答后说明这道题在检验什么，以及用户可能忽略了哪个边界。
- 支持“不确定”，不强迫用户站队。

完整路线已升级为“终点 + 分阶段任务 + 现实反馈”：

- 每个任务包含时间窗口、验证假设、执行渠道、操作步骤、完成标准、继续信号、停止信号和对应观点。
- 用户可以标记“做过”，并回填“路是通的 / 前面塌方了 / 雾还没散”及自由备注。
- 完成结果会写回这次山径，用于之后调整推荐，而不是只保存一个静态结论。

## 6. 真实来源与演示数据

本轮重点修正了“示例文章看起来像真实文章”的问题。

- 真实模式会检索知乎站内和全网内容，分别排序、去重后再合并；知乎内容充足时保持为主体，全网只作补充。
- 模型只能引用本次检索结果的编号，后端再把编号映射回标题、URL、作者、摘要等真实字段，不直接采用模型生成的文章链接。
- 演示模式的素材没有伪造外链、赞同数或作者身份，统一标记为“演示素材，不对应真实知乎文章”。
- 演示记录不会进入下一轮真实历史注入，避免示例结论污染后续判断。
- 直答失败但检索成功时，会展示真实检索到的原始来源，并明确说明没有经过二次整理。
- 总览和观点墙现在会按实际来源状态展示“知乎来源 / 全网来源 / 暂无可核验原文 / 演示素材”，不再固定声称内容来自知乎。
- 如果没有可核验原文，界面会把内容称为“待验证假设”，不会称为真实知乎观点。

这里需要保持诚实：当前实现能保证展示的链接来自真实检索结果，但还不能保证 AI 总结中的每一句话都被对应原文逐句支持。因此产品使用“观点与原文”“打开原文核对”等表述，不使用“绝不造假”“已经完全核验”之类承诺。

## 7. 历史山径与长期记忆

当前不做账号系统，历史以浏览器本地存储为主，最多保存 30 条。

- 一次分析成功后会自动存档，可回看当时的处境、观点、自测、路线和现实反馈。
- 新问题只选择与当前主题共享核心实体的历史，最多使用 3 条；完全无关的历史不注入。
- 历史会保留最信观点、未确认盲区、完成任务、现实结论和用户备注。
- 下次生成时，已证实的判断可少重复，被现实推翻的方向会降低优先级，未明确部分继续验证。
- 页面会列出本次实际参考的历史主题，并显示“判断发生变化”或“仍然保持原判断”，不会悄悄覆盖旧结论。
- 支持山径档案 JSON 导出和导入，作为无登录情况下的低成本跨设备方案。
- “清空本地记录”只删除本产品使用的 `alchemy:*` 数据，不影响同域下其他产品。

隐私边界：历史主要保存在本地，但用户发起新分析时，相关历史的精简摘要会发送到本项目后端；用户主动和刘看山聊天时，当前结果及必要历史文本也会发送到后端用于回答。不能对外宣传成“历史永远不会离开浏览器”。

## 8. 简历隐私与服务端安全

- PDF、DOCX、TXT、Markdown 和图片原文件只在浏览器读取。
- 比赛后端已关闭 `/api/parse-doc`，收到原文件上传请求会返回 `410 FILE_UPLOAD_DISABLED`。
- 浏览器提取出的文字会在用户知情后发送到后端，并交给已配置模型做结构化整理；上传和粘贴均可跳过。
- 未勾选知情确认时不会开始解析，并提供明显的动效与错误提示。
- 模型提取、确认表、本地存档和服务端返回均移除姓名、手机号、邮箱等直接身份字段。
- 比赛版本明确关闭 `/api/oauth/*`，返回 `501 OAUTH_DISABLED`；当前方案不引入登录和 OAuth 成本。
- Access Secret 只由服务端读取，不进入前端。真实 `.env` 已被 Git 忽略，本次提交不包含它。
- API 增加统一安全响应头、请求方法校验、请求体大小限制和一致的错误信封。

## 9. 额度保护与稳定性

- 新增 `DEMO_MODE=true`，可强制走完整演示流程，不消耗真实搜索或直答额度。
- 热榜、搜索、炼金、行动、简历和聊天接口增加分客户端窗口限流。
- 部署实例增加按北京时间计算、写入 `.cache` 并可跨重启保留的全局日预算。
- 主流程会一起预留搜索和 AI 预算，避免只扣一半后留下不完整状态。
- 达到预算保护线后切换到演示或兜底结果，并向前端明确显示原因。
- 限流响应带 `Retry-After`；JSON 错误、超大请求和不支持的方法都有稳定错误码。
- 加载和失败提示改成人话，并尽量保留用户已填写内容，避免失败后重新建档。

## 10. UI 视觉与可用性

- 主色回到知乎蓝，辅以低饱和山头色和远山线条，保留“看山”的路径感。
- 减少装饰性 emoji、渐变和厚重卡片感，圆角与控件视觉更统一。
- 山头颜色贯穿观点墙、自测和行动路线，完成节点使用旗帜与山径反馈表达状态。
- 增加键盘操作、焦点样式、ARIA 状态、错误播报和弹层焦点回收。
- 补齐移动端单列布局、长文本防溢出和 `prefers-reduced-motion` 支持。
- 新增站点图标，并把刘看山官方透明动图用于常驻助手和加载状态。

## 12. 已知限制和下一步风险

这些问题本轮没有隐藏，后续继续做时应优先看：

1. 当前无登录和云同步，跨设备只能手动导出、导入。
2. “开始这一步”尚未持久化当前小任务；刷新页面后不会恢复它的开始状态。
3. 分析成功目前自动存档，还没有实现“任务完成后再询问是否保存”的完整确认流程。
4. 完整路线需要至少完成 4 道自测，并可能额外调用 AI；网络慢或额度不足时会回到初版或兜底路线。
5. 链接来自真实检索结果不等于观点已经逐句事实核验。真实结果为 0 时只能展示待验证假设，下一步应进一步限制模型只生成取证任务。
6. 历史相关性目前依赖实体词和同义词规则，不是语义向量检索；策略偏向少带历史，避免乱带。
7. 知乎素材不足时，全网来源占比可能提高，因此所有页面必须继续按实际来源类型展示，不能固定写“知乎真实观点”。
8. 生产主包约 717.15 kB，gzip 后约 214.21 kB；PDF worker 约 1.38 MB。后续需要继续拆包和按需加载。
9. `docs/2026-09-05-三项修复设计定论.md` 是历史设计稿，其中部分“尚未实现”的描述已过期，以本文和当前代码为准。

## 14. 队友本地启动

```bash
npm install
npm run dev
```

没有真实密钥时会自动进入演示模式。需要在有密钥的机器上仍强制走演示流程时，在 `.env` 中设置：

```dotenv
DEMO_MODE=true
```

不要提交真实 `.env`、Access Secret、OAuth Token、App Key 或任何用户简历原文。
