# 山外山最终提交交接说明

更新时间：2026-09-13  
当前版本：最终提交版  
GitHub：<https://github.com/slowhot112/beyond_mountain>  
公网 Demo：<https://shanwaishan-production.up.railway.app/>

## 先看结论

这次不是单纯调整颜色和排版，而是把产品主线收敛成一条完整的求职判断链路：

`标记处境 → 查看知乎真实观点 → 辨向自测 → 做现实验证 → 回填结果 → 用户确认变化 → 行动簿长期记录 → 下次按处境选择是否带入`

核心原则是：现实可以提出变化，但系统不能悄悄替用户改写判断；任何会影响下一次使用的变化，都必须先展示，再由用户确认。

## 1. 产品定位的最终收敛

- 知乎负责提供真实社区观点、经验和来源。
- 山外山负责把不同观点按用户处境重新组织，帮助用户形成自己的判断。
- 行动路线负责把判断变成可执行的验证动作。
- 行动簿负责记录“我曾经怎么判断，现实后来告诉了我什么”。
- 刘看山负责关键时刻的陪伴和提醒，不承担唯一入口，也不能代替用户对外行动。
- 不做登录，不做云端账号体系，优先保证低成本、可演示和隐私边界清晰。

## 2. 主要 UI / UX 改动

### 首页与导航

- 首页新增独立“行动簿”入口，并显示当前等待处理或正在验证的记录数量。
- 结果页顶部、结果导航和行动路线都能进入行动簿。
- “出师清单”升级为“成果行囊”，不再把成果当作一次性待办任务。
- 页面切换后会清理旧错误、回到合理的阅读位置，并保留本轮访问进度。

### 观点墙

- 默认先展示一条值得优先阅读的观点，其余观点先显示摘要。
- 每条观点统一呈现：主张、最强论据、适用处境、成立边界、对其他观点的质疑、匹配理由和原文来源。
- 来源说明按真实状态区分：知乎来源、全网来源、原始检索结果、暂无可核验原文、演示素材。
- 不再使用“汤家凤”“车辆工程考研”“人生修炼手册”等与当前产品逻辑无关、容易出戏的答主标签。
- 不再把用户表述为“最信某位答主”，改为“本轮答题更多接近某种观点”。

### 辨向自测

- 题目、答题区、解读区做了物理分区，避免题干、选项和蓝色复盘文字挤在一起。
- 每道题都绑定当前观点墙里的具体前提，不再是泛化性格测试。
- 选项来自对应观点的真实立场缩写，不显示 `r1/r2/r3` 或“某派”等内部代号。
- 支持“不确定”，不强迫用户站队。
- 每题回答后只先显示轻量回响，长解释按需展开。
- 至少完成 4 道题后才允许生成完整路线，避免低置信度结果被包装成确定结论。

### 行动路线

- 先给一个短时间、低沉没成本的现实验证动作，再展开较长周期路线。
- 每个行动包含：时间窗口、要验证的判断、执行渠道、操作步骤、完成标准、继续信号、停止信号和服务的观点。
- 现实结果必须先填写事实记录，之后才能选择“符合 / 不符合 / 还不能判断”。
- 证据链接可选，现实事实必填。
- 结果回填后进入行动簿的“等待确认变化”，不会直接成为长期记忆。

### 行动簿

行动簿是最终版新增的长期陪伴核心，包含两个视图：

#### 判断时间线

默认优先级为：

1. 等待确认变化
2. 正在验证
3. 当前处境相关
4. 已确认回看

每条判断会记录：

- 判断形成时间
- 来源山径
- 原始判断
- 现实事实
- 系统提出的候选变化
- 用户最终确认的处理方式
- 这次选择会怎样影响下一次使用

用户可选择：

- 保留原判断
- 修正条件
- 暂不改变
- 放下这条判断

“修正条件”由结构化条件维度加一句用户补充组成。系统只提供候选框架，必须经过用户确认才会进入长期记录。

#### 成果行囊

行囊聚合多条山径中形成的成果，包括：

- 岗位地图
- 能力差距清单
- 调研与试用记录
- 评测记录
- 作品
- 简历
- 面试准备
- 投递记录
- 能力证明

为避免信息过载：

- 成果按类型分组。
- 每组默认只显示前两项。
- 详细内容使用可展开行展示。
- 超出部分通过“再看 N 项”展开。
- 相似成果集中在一个整理区，不再连续铺开多块合并提示。

同类型成果可以建立“持续更新的母本”，但必须由用户主动确认。母本只改变展示方式，不覆盖原始记录；来源、更新时间和原记录都可追溯，也支持“拆回原记录”。

### 历史判断带入

- 历史判断默认不会自动套用。
- 新问题与旧处境相近时，先展示相同条件和不同条件。
- 用户确认后，旧判断只作为“需要重新核对的参考前提”，不会替用户作答。
- 选择“暂不改变”或“放下”的判断不会进入下一轮自动参考。

### 刘看山

- 常驻右下角，保留知乎生态识别度。
- 只在关键时刻介入，例如问题填写完成、结果生成、开始验证、现实结果带来变化。
- 提醒采用轻量气泡，不弹窗打断主流程。
- 可以帮助用户准备资料、解释结果和提出建议。
- 不能未经确认代替用户投递、联系、发布或提交任何对外内容。

## 3. 真实来源与防造假处理

- 真实模式分别检索知乎站内和全网内容，再去重、排序和合并。
- 模型只能引用本次检索结果编号，后端负责映射真实标题、作者、摘要和 URL。
- 不直接采用模型生成的文章链接。
- 真实来源不足时明确显示“相近主题”或“待验证假设”。
- 演示素材明确标记为演示内容，不冒充真实知乎文章。
- 已清理产品界面中的内部角色代号、虚构答主标签和容易误导的“最信”表述。

需要注意：真实链接来自检索结果，不等于模型总结中的每句话都已经逐句事实核验。因此产品文案使用“观点与原文”“打开原文核对”，不做“绝不造假”或“完全核验”的过度承诺。

## 4. 数据、隐私和权限边界

- 当前不做登录和 OAuth。
- 历史山径和行动簿主要保存在浏览器本地，最多保留 30 条记录。
- 支持导出、导入山径档案，用于低成本跨设备迁移。
- 简历原文件在浏览器端读取，不上传原始文件；用户可以完全跳过简历。
- 本地存档会移除姓名、手机号、邮箱等直接身份字段。
- “清空本地记录”只清理本产品的 `alchemy:*` 数据。
- 真实模式下，发起新分析或使用刘看山时，必要的处境摘要和相关历史可能发送到后端；不能宣传为“历史永远不会离开浏览器”。

## 5. 技术与部署

- 前端：React 18 + Vite 5。
- 后端：Node.js 单进程服务，同时托管 `dist/` 和 API 代理。
- 知乎能力：知乎搜索、全网搜索、知乎直答、热榜和额度保护。
- 失败时有演示数据和兜底路线，不会白屏。
- Railway 服务已连接 GitHub 仓库 `slowhot112/beyond_mountain` 的 `main` 分支。

## 7. 队友本地启动

```bash
npm install
npm run dev
```

本地地址：<http://localhost:5173/>  

没有真实密钥时会自动进入演示模式。正式演示前建议：

1. 先打开公网 Demo，确认首页能加载。
2. 从“标记我的位置”开始走一遍主流程。
3. 在观点墙点击“查看来源”，确认来源说明和外链正常。
4. 在行动路线完成一条准备动作，再回填现实事实。
5. 打开行动簿，展示“等待确认变化”和“成果行囊”。
6. 演示时明确说明：现实结果不会自动改写用户判断。

## 9. 已知但不阻塞提交的事项

- 主 JavaScript 包体积约 748 kB，构建会提示超过 500 kB；当前不影响加载和比赛演示。
- 无登录和云同步，跨设备需要手动导出、导入档案。
- 现实验证目前保存事实和结果，但没有接入外部招聘平台的自动回执。
- 历史相关性使用规则筛选，不是向量检索，策略偏向少带历史，避免误带。

这些事项没有隐藏，均不影响当前最终版的核心产品闭环和公网演示。
