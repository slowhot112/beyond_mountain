# 山外山最终版交接：行动簿与长期陪伴闭环

更新日期：2026-09-13

## 一句话说明

这次把原来一次性的“行动清单”收束为长期能力“行动簿”：用户先从知乎真实观点中形成判断，再用一个低成本现实动作取证；现实结果只会提出变化，必须由用户亲自确认，才会影响下一次使用。

## 最终产品主线

`标记处境 → 查看真实观点与适用条件 → 辨向 → 做一次现实验证 → 回填事实 → 确认判断变化 → 留进行动簿 → 下次按相似处境选择是否带入`

行动地图仍然保留，但它不再是产品的终点。它负责承接较长周期的执行；行动簿负责保存判断如何被现实修正，以及执行过程中形成的可复用成果。

## 本次最终改动

### 1. 新增独立“行动簿”

- 首页、结果页顶部和行动路线都能进入，不依赖刘看山作为唯一入口。
- 默认展示“判断时间线”，优先级固定为：等待确认变化、正在验证、当前相关、已确认回看。
- 每条判断都保留形成时间、来源山径、现实事实、候选变化、用户确认和对下一次使用的影响。
- 刘看山只在关键时刻提醒，例如有现实变化等待确认时，不持续打断用户。

### 2. 现实证据不会静默改写用户

现实结果回填后，状态先进入“等待确认变化”。用户可在卡片内选择：

- 保留原判断
- 修正成立条件
- 暂不改变，继续收集证据
- 放下这条判断，不再主动带入新问题

“修正条件”使用结构化条件维度加一句用户补充。系统只能提出整理框架，用户确认前不会写入长期记忆。

### 3. 历史判断按需带入

- 历史判断默认不会自动套用。
- 新问题与旧处境相近时，页面会先列出相同条件和不同条件。
- 用户选择带入后，它也只作为需要重新核对的参考前提，不会替用户回答。
- 选择“暂不改变”或“放下”的判断不会被喂给下一轮。

### 4. “出师清单”升级为成果“行囊”

- 岗位地图、能力差距清单、调研与试用记录、评测记录、作品、简历、面试准备、投递记录等成果统一进入行囊。
- 行囊按成果类型分组，每组默认只显示两项，详细内容按需展开，避免几十张卡片同时铺满页面。
- 同类型成果可建立“持续更新的母本”，但必须由用户确认。
- 母本合并只改变展示方式，来源和历史更新仍可追溯，也能随时拆回原记录。
- 所有合并建议收进一个轻量整理区，避免连续提示抢占注意力。

### 5. 文案与界面收尾

- 清理用户界面中的 `r1/r2/r3`、派别代号、“最信某位答主”和“该答主认为”等内部或欠考虑表述。
- “第一版/第二版”改为可运行作品、可比较基线，符合本次最终交付定位。
- 行动簿采用渐进披露：先看状态和摘要，再展开时间线、条件确认、成果详情与更新记录。
- 补齐窄屏单列布局、长标题截断、触控命中区、键盘焦点和减少动效偏好。

## 数据与权限边界

- 当前不做登录，历史和行动簿保存在浏览器本地。
- 支持导出、导入山径档案，作为低成本跨设备方案。
- 刘看山可以准备材料、解释结果和提出建议，但不能未经确认替用户投递、联系、发布或提交资料。
- 所有会影响下一次判断的变化都必须先展示，再由用户确认。

```bash
npm install
npm run dev
```

访问 `http://localhost:5173/`。没有真实密钥时会走演示兜底；正式演示前请确认环境变量和知乎开放平台额度正常。

## 重点文件

- `src/components/ActionJournal.jsx`：判断时间线、变化确认、成果行囊和母本交互
- `src/components/MemoryCarryover.jsx`：历史判断相同/不同条件对照与带入确认
- `src/journal.js`：判断状态、排序、成果归类和相似历史选择
- `src/components/ActionMap.jsx`：现实事实回填、等待确认与成果行囊入口
- `src/components/Landing.jsx`：首页行动簿入口与状态摘要
- `src/components/SpiritGuide.jsx`：刘看山在关键时刻的提醒
- `src/App.jsx`、`src/lib.js`：跨页面状态、存档、导入导出和长期反馈边界
- `src/styles.css`：最终 UI、响应式和交互状态
- `scripts/linkage-check.mjs`：新增行动簿闭环回归检查
