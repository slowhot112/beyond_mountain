## 一、产品定位

**一句话**：一个面向"想入门新领域、却被知乎上互相矛盾的高赞经验搞懵的新手"的 AI 陪练工具——**它不替你下结论，而是把冲突观点摆成对峙、教你判断、逼你产出自己的立场**。

**更完整的定位**：在知乎的"信息过载 + 高赞互撕"场景里，帮用户把"看了一堆还是不会判断"变成"看清分歧、长出自己的判断"。我们刻意**不做总结机器**，而是做"判断力陪练"。

- **赛道**：知乎黑客松·校园新锐季 —— 知识炼金场
- **形态**：Web 应用（前端网页 + Node 后端，零数据库、零三方依赖）
- **人群**：学生 / 职场新人为主，通用人群也可
- **核心差异化**：多视角工具大多"综合成单一结论"，我们**反着来**——保留分歧张力，把判断责任还给人。

## 二、预期效果（对用户 / 对评审）

| 对象 | 预期效果 |
|---|---|
| 新手用户 | 输入一个纠结的话题，几秒内得到"三种立场对峙 + 信谁框架 + 判断力自测 + 行动清单"，从"被高赞带节奏"变成"会自己判高赞"。 |

| 赛事价值 | 用知乎官方 IP（刘看山）做三种辩论形态，贴合"知乎生态契合度"；帮新手成为更好的知乎使用者，反哺社区讨论质量。 |

## 三、都有什么功能（四大模块）

| 模块 | 形态 | 解决什么 | 交互 |
|---|---|---|---|
| ⚔️ **刘看山辩论台** | 三张可翻转卡 | 把"互相矛盾的高赞"变成可见的对峙 | 点卡翻面：正面=论点论据，背面=2 篇可点击的知乎来源文章 |
| 🧭 **信谁框架** | 决策维度卡 | "怎么自己判"而非给答案 | 阅读即可 |
| 🎯 **判断力自测** | 交互题 | 逼用户产出立场、而非选知识答案 | 选立场 + 写理由 + 点"看反馈"揭示盲区 |
| 🚶 **行动地图** | 可勾选清单 | 把想法落成这周能做的 3 件小事 | 勾选进度按"话题+模式"存本地，刷新仍在 |

**附加能力**
- 话题自适应：演示模式输入任意话题都生成连贯内容（不穿帮）。
- 多人群模式：🎓职场新人 / 📚在校学生 / 🌱通用，侧重点不同。
- 热榜灵感：首页蓝色标签一键换话题。
- 导出 Markdown + 打印存长图/PDF（零新增依赖）。
- 来源可溯源：每个论点挂真实知乎文章链接（接 Secret 后精确到具体回答）。

## 四、讲了什么故事（叙事 / Why）

**用户故事**：一个想转行/准备面试/纠结考研的学生，刷知乎时每条高赞都像真理，合起来却互相矛盾。他不是缺信息，是**缺在信息洪流里长出自己判断的能力**。

**我们的故事线**：
1. 知乎内容天然"多声喧哗、互相打架"——这是痛点，也是金矿。
2. 多数 AI 工具急着"综合出一个答案"，反而让用户更不动脑。
3. 我们让**刘看山分裂成三种形态辩论**（实干家/谋略家/联结者），把分歧摆出来。
4. 再用"信谁框架 + 判断力自测 + 行动地图"，把"看清"推进到"长出判断、落地行动"。
5. 结尾不替用户定论——**判断留给你**。

> 一句话 slogan：**不综合结论，判断留给你。**

## 五、如何参考官方给的项目（知乎黑客松官方资源）

我们严格基于赛事官方 Skill 包 `zhihu-hackathon-skill` 的文档实现，不是自己猜 API：

- **API 依据**：`zhihu-hackathon-skill` 中的 `http-api.md`（知乎搜索、热榜）、`user-api.md`、`open-platform.md`（直答大模型）。
- **鉴权方式**：采用官方"Access Secret + Bearer"方案，**免 OAuth、无需用户登录**，降低 Demo 部署与评委体验门槛。
- **IP 联动**：使用官方提供的刘看山 IP，作为辩论形态载体；遵守"仅比赛期使用、需规范声明归属知乎"的合规要求（合规声明见 `NOTICE` 占位）。
- **部署契合**：官方鼓励公网可体验的作品，我们用单进程 Node 服务（无数据库）天然适配 Railway / Render 等免费 PaaS。

## 六、GitHub 上参考了哪些（竞品调研，`references.md` 可查）

我们做了 7 个真实、可验证的 GitHub 开源项目调研，结论是"多视角 + 不综合 + 训练判断"方向已有人做、但都偏通用/决策领域，**没有锚定"知乎新手学习"——我们的空白成立**：

| 项目 | 链接 | 与我们相似点 | 差异 |
|---|---|---|---|
| both-sides-research | https://github.com/PSkinnerTech/both-sides-research | 钢人论证呈现对立最强论据，不丑化对方 | 它最终仍给结论；我们坚持不替用户定论 |
| DialecticEngine | https://github.com/dai-zw/DialecticEngine | 多视角推理 + 完整 Web 前端 | 含"辩证综合"，我们弱化综合、强化留白 |
| devils-advocate | https://github.com/kiingsai/devils-advocate | 合成结论后强制魔鬼辩驳攻击 | AI 先给结论；我们让人先产立场再被攻击 |
| multi-agent-debate | https://github.com/ChetanyaRathi/multi-agent-debate | 交互式多角色辩论 + 主席引导 | 最终投票综合；与"不综合"相反 |
| debate-ai | https://github.com/1311523821/debate-ai | 双模型对抗辩论（轻量 Web） | 走向 consensus |
| concilium-llm | https://github.com/G00gleKid/concilium-llm | CLI 多专家辩论产加权共识 | 综合结论，反衬我们差异化 |
| Multi-Agents-Debate | https://github.com/Skytliang/Multi-Agents-Debate | 学术界多智能体辩论框架（605★） | 纯框架无 UI，背书方向成立 |

**方法论借鉴**：直接采用 `both-sides-research` 的"钢人论证"做对峙墙；参考 `devils-advocate` 的"魔鬼辩驳"做自测反馈。

## 八、队友快速上手（技术）

- **运行**：`npm start` → 打开 `http://localhost:3000`（默认演示模式）。
- **接真实数据**：报名拿到 Access Secret 后，写入 `.env` 的 `ZHIHU_ACCESS_SECRET`，重启即切 LIVE。
- **部署公网**：见 `DEPLOY.md`（Railway / Render 三步）。
- **目录结构**：
  - `server.mjs` 轻量后端（托管前端 + 代理知乎 API）
  - `zhihu.js` 知乎客户端（搜索 / 热榜 / 直答 + 文件缓存 + Mock 兜底）
  - `public/` 前端（index.html / app.js / styles.css）
  - `references.md` 竞品调研 · `plan-material.md` 生态价值素材 · `DEPLOY.md` 部署说明
- **关键约束**：直答仅 100 次/天 → 按话题文件缓存；无 Secret 时走话题自适应 Mock，永不白屏。
