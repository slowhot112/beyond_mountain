# 山外山 产品说明计划书

> 把知乎真实经验，变成可以亲自验证的下一步

## 项目概述

山外山是一款基于知乎真实求职经验的判断助手。它按用户当下的阶段、目标、方向、城市和时间压力，整理知乎社区中的不同观点，展示每条观点的适用处境、成立边界和原文来源。用户先形成自己的暂时判断，再完成一个低成本现实验证，最后把“当时怎么判断、现实告诉了什么”记录进行动簿。

产品不输出标准答案，也不会让 AI 越过用户替用户投递、联系或发布。

## 核心流程

`标记处境 → 查看观点与原文 → 辨向自测 → 一个小验证 → 回填事实 → 用户确认变化 → 行动簿长期记录`

1. 标记处境：写下“你现在最想判断什么”，其余信息按需补充。
2. 查看观点：分别检索知乎站内与全网内容，按主张、依据、适用处境、成立边界和来源组织。
3. 选择要核对的判断：标记像我的处境、前提不适合我、我还拿不准，或加入验证。
4. 辨向自测：题目绑定观点前提，允许不确定，不强迫站队。
5. 小验证：先做今天能完成、沉没成本低的现实动作。
6. 回填并确认：现实结果先进入等待确认，用户选择保留、修正、暂不改变或放下。
7. 行动簿：保存判断时间线，成果行囊保存可跨山径复用的成果。

## 知乎生态价值

- 让优质职业回答从被动刷到变成处境化发现。
- 保留问题、回答和作者语境，提供原文入口。
- 将社区经验连接到用户自己的现实验证，而不是只停留在内容消费。
- 以刘看山作为关键节点陪伴角色，连接知乎内容与产品体验。

## 技术方案

- 前端：React 18 + Vite 5 + 原生 CSS。
- 后端：Node.js 原生 http，托管 dist 并代理 API。
- 知乎能力：知乎搜索、全网搜索、知乎直答、热榜、额度查询。
- 存储：浏览器本地存储 + JSON 导入导出；可选知乎 OAuth 同步。
- 解析：浏览器端 PDF/DOCX 文本提取与 OCR，提取结果必须由用户确认。

真实来源由检索结果提供，模型只能引用本次检索结果编号，后端负责映射标题、作者、摘要和 URL。来源不足时明确标注相近主题、待验证假设或演示素材。

## 用户控制与隐私

- 历史判断默认不自动套用，相似条件和差异先展示。
- 现实证据只能提出变化，不能静默改写判断。
- 任何影响下一次使用的变化，都要先由用户确认。
- 刘看山只准备材料和解释页面，不代替用户对外行动。
- App Key、Access Secret、OAuth Token 和同步密钥只在后端或部署平台 Secret 中使用。
- 游客模式可完整使用，登录不是主流程前提。

## 参考项目吸收

吸收了“人生未定式”的单一主入口、“故事之外”的渐进展示、“活答案”的来源状态与可追溯更新、“思想引力场”的多观点并列、“归遥/问山”的小步反馈与长期上下文，以及 ArguMesh 的 React + Vite、本地优先和证据溯源理念。

实时多 Agent 辩论、投票共识、自动投递和完整社交分享没有纳入本次 MVP，用于保持主线清晰、控制 API 消耗并守住用户授权边界。
